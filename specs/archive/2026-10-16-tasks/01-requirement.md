# 需求规格：tasks

## 1. 用户故事与主流程

作为个人用户，我希望维护一个简单的任务列表，以便跟踪待办事项。

- F1 添加任务：输入标题 → 点击添加 → 任务出现在列表顶部，状态为"待办"
- F2 切换状态：点击状态按钮，按 待办 → 进行中 → 已完成 → 待办 循环
- F3 删除任务：点击删除 → 任务从列表消失
- F4 查看列表：按创建时间倒序；刷新页面后数据仍在

## 2. 范围外（Out of Scope）

- 登录与多用户（接口预留 UNAUTHORIZED / FORBIDDEN 错误码，前端处理无权限状态）
- 任务描述、截止日期、标签、拖拽排序
- 撤销删除与回收站界面（数据层做软删除，但不提供恢复入口）

## 3. 假设

- 单用户，无需鉴权（若不对请纠正）
- 页面一次最多展示 50 条，暂不做"加载更多"（若不对请纠正）

## 4. 开放问题

| ID   | 问题                            | 影响面       | 默认选择               | 结论               |
| ---- | ------------------------------- | ------------ | ---------------------- | ------------------ |
| OQ-1 | 删除是物理删除还是软删除？      | db、api      | 软删除（deleted_at）   | 同意默认           |
| OQ-2 | 标题长度上限？                  | shared、web  | 200 字，去除首尾空格   | 同意默认           |
| OQ-3 | 分页方式用 offset 还是 cursor？ | api、Android | offset，limit 上限 100 | offset，数据量很小 |

## 5. 异常态

- loading：列表加载中显示"加载中…"
- empty：没有任务时显示引导文案
- error：加载失败显示错误信息与"重试"按钮；单条操作失败在该条下方提示
- 无权限：接口返回 UNAUTHORIZED / FORBIDDEN 时显示"无权限查看任务"
- 并发冲突：不适用（单用户）
- 断网：按 error 处理，可重试
- 幂等：重复提交同一标题会创建两条，可接受，不做去重

## 6. 非功能需求

- 性能：列表接口本地 p95 < 100ms；分页 limit 上限 100
- 权限：暂无（见范围外）
- 国际化：仅中文
- 无障碍：输入框有 aria-label；状态提示使用 role=status / role=alert
- 埋点：不需要

## 7. UI 规格

- 无设计稿：使用 packages/ui 默认样式（Card / Input / Button）
- 组件：任务卡片 = 标题输入框 + 添加按钮 + 任务列表（标题、状态按钮、删除按钮）
- 交互态：提交中按钮显示"添加中…"并禁用；已完成任务标题加删除线
- 暗色模式：跟随系统（globals.css token）
